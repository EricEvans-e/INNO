\section{详细设计与实现}
\subsection{空间放置与副本管理}
映射器提供 First Fit、Best Fit 和 aspect-aware 三类装箱策略。基线按顺序选择首个可用位置；优化方案以 Best Fit 为主体，通过剩余空间、形状碎片、分组一致性和已有负载选择候选位置。对于热点专家，副本数由频率、争用、burstiness 和转移影响形成的压力得分决定，并受到额外物理体积预算限制。副本优先分散到不同 Sub-Cube，以避免将逻辑副本重新聚集为同一资源瓶颈。

MoE 优化首先进行多起点互斥分组，再按组需求和组间共现构造分配问题。热点组可在 top-$k$ 范围内用分支定界精确分配，剩余组采用局部迁移、交换和模拟退火改进。该过程并不替代物理装箱：组分配只提供放置偏好，最终仍由 3D 坐标可行性决定是否成功放置。

实际部署流程按以下顺序执行：首先由模型形状生成不可旋转的水平或垂直切分；其次统计专家频率、共现、转移和 burstiness，并生成互斥分组；然后为热点专家计算副本请求，在额外体积预算内尝试跨 Sub-Cube 放置；最后以几何可行的候选放置为输入运行静态调度。若副本不能同时改善可行性或预计等待时间，映射器保留逻辑映射而不强行复制。这一顺序保证复制是受预算控制的物理决策，而不是仅在结果表中声明的逻辑属性。

副本请求不是按频率单一排序。对专家 $i$，实现将频率、资源争用、burstiness 和转移影响归一化后组成压力分数
\begin{equation}
P_i=w_f\hat f_i+w_c\hat c_i+w_b\hat b_i+w_t\hat t_i,
\end{equation}
其中权重由运行参数显式记录。超过高压力阈值的专家优先申请副本，低于低压力阈值的专家不主动复制，中间区域则由剩余容量和调度预估共同决定。每次申请都经过体积预算、坐标边界和跨 Sub-Cube 分散检查；申请失败时回退到单副本映射，因此“请求副本数”不等于“实际物理副本数”。

\subsection{静态调度与约束验证}
模拟器将每个推理实例展开为任务图。仅被轨迹激活的路由专家生成计算任务，共享专家并入激活集合。就绪任务按照 FIFO 或关键路径优先策略选择候选物理副本；调度器计算每个候选副本的依赖释放时间、Sub-Cube 空闲时间、切换惩罚、z 层代价和带宽压力，并选择最早可完成的方案。可选的线性或带宽/z 感知非线性模型用于估计传输/计算重叠收益。

对每个就绪任务，调度器先过滤违反前驱屏障、Sub-Cube 互斥或物理副本一致性的候选，再对剩余候选计算最早开始时间和完成时间。选择完成时间最小的候选；若完成时间相同，则依次比较切换次数、z 层深度和副本负载。任务完成后更新对应 Sub-Cube 的空闲时间、上一任务标识和带宽状态，直至任务图清空。这个贪心过程不保证全局最优，但输出具有确定性，且每一步的选择都可以由 schedule 和 run manifest 复核。

调度器的执行过程可以概括为以下五步：
\begin{enumerate}
\item 将每条推理记录展开为共享算子、路由专家和合并算子任务，并根据算子 DAG 建立前驱集合；
\item 将前驱全部完成的任务加入就绪集合，按照 FIFO 或关键路径优先策略取出任务；
\item 对每一个可用物理副本计算依赖释放时间、所属 Sub-Cube 空闲时间、切换项、z 层项和带宽项；
\item 选择最早完成的合法候选，写入任务的开始时间、结束时间和物理副本 ID，并更新资源状态；
\item 重复上述过程直到任务图清空，再由独立验证器重新检查 schedule，而不是直接信任调度器内部状态。
\end{enumerate}

当多个前驱汇聚到共享的下游算子时，调度器取前驱完成时间的最大值，形成严格 barrier；因此不同 Sub-Cube 之间可以并行，并不意味着下游任务可以提前消费部分未完成的专家结果。该处理是区分“资源并行”与“依赖并行”的关键，也解释了为什么仅观察放置图不能推出端到端延迟。
